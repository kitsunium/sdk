| `adr/0050-sdk-lifecycle-domain.md` | Ordered start/stop domain (`lifecycle`): the SDK had every piece of a service's startup and no assembly of them, and **two lifecycle defects found in this repository are the argument** — ADR 0043 (one endless stream spent the entire drain budget, making `DRAIN_TIMEOUT` the normal outcome of every deployment) and ADR 0047 §D9 (the engine closed the socket it had just handed to the handler, so no hijack worked at all). | `adr/0053-sdk-events-domain.md` | In-process event bus domain (`events`), and **the line between it and the `queue` domain that comes next** — drawn before either could drift, because a library that "supports both" reliably guarantees neither. `events` is in-process, synchronous, same-goroutine, same transaction: no durability, no retry, no dead-letter path, and if the process dies mid-dispatch the event never happened. A caller who wants "asynchronous but reliable" is sent to `queue`, not served the asynchrony without the reliability — so there is deliberately no async mode, not even as an option (§Why not). The routing key is the event's concrete Go TYPE, never a name: the compiler mints it, two packages cannot both spell `"user.created"`, and an interface type is REFUSED at registration because `reflect.TypeOf` never yields one and such a listener would be listed and never called (ADR 0031). ## ADR conventions

- Sequential numbering (`0001`, `0002`, …). Never reuse a number.
- Filename slug = short kebab-case summary of the decision.
- Header fields: `Status`, `Date`, `Deciders`, optional `Supersedes`, `Superseded by`, `Amends`, `Amended by`, `Closes`, `Related`.
- Standard sections, in this order: Context, Decision, Consequences / Semantics, Breaking changes, Alternatives considered and/or Why not …, Deferred, References. This is the same list as `docs/adr/CLAUDE.md` §Conventions — keep the two in step. Both forms are in use: ADRs 0093 to 0138, 0141 and 0142, and many older ones, have an `## Alternatives considered` section, some with `### Why not …` headings under it; ADRs 0139 and 0140, and many older ones, have a `## Why not …` section. This line named "Why not …" alone after that file listed both, and an automated review read the omission as a rule and flagged the heading.
- Immutable after merge. Supersede via a new ADR that references the old one (e.g. ADR 0005 supersedes ADR 0002 §Registry; ADR 0006 amends ADR 0005 §Registry).
- The cross-cutting principles are ADR 0154's numbered list (the charter); a principle changes only by an ADR amending 0154.
- A path in an ADR is the path of its time (ADR 0155): a moved package takes its `CLAUDE.md`, the enforcement artefacts and the three indexes with it, never an ADR's body; only an older ADR's `Status` and `Amended by` lines are re-pointed. Same rule as `docs/adr/CLAUDE.md` §Conventions.
- An incident ADR — a defect found, reproduced and fixed — is folded, then superseded (ADR 0154 §2): its rule goes into the `CLAUDE.md` of the package or script it protects, under `## Rules from ADR NNNN`, its `Status` becomes `Superseded by 0154` naming that file, and its text stays as the record. Same rule as `docs/adr/CLAUDE.md` §Conventions.

## Registry coupling

The dotted-quad allocation table in `adr/0005-…` + the extension in `adr/0006-…` is the **documentary source of truth**; the hand-maintained `codeRangeOwners` table in `internal/kernel/errs/registry_ownership_external_test.go` is the **executable source of truth** (ADR 0035). Keep the two in sync manually on every change — the ownership audit fails on a range absent from that table, and `registry_external_test.go` catches drift on uniqueness and `reason = screamingSnake(varName)` OR `screamingSnake(CodeConst − "Code")` (ADR 0006/0020) over every package in `//:audit_sources`.

`docs/error-codes.yaml` is the **generated human-readable mirror** of every `errs.Code` constant in the tree (one entry per code: dotted-quad, const name, hex, package). Regenerate with `make error-codes` (`scripts/gen-error-codes.sh`); the `scripts/pre-commit/check-error-codes-drift.sh` guard fails `make lint` and CI when it is stale. It is a convenience index, not authoritative — the AST audit remains the executable gate.

## Do NOT

- Put feature documentation here. Packages document themselves via `README.md` next to their code.
- Delete an accepted ADR. Mark it superseded by adding a new ADR and updating both `Status` lines.
- Re-number existing ADRs, even after a supersede chain.
- Edit an ADR's Decision section after merge — write a new ADR.
