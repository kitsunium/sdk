# internal/core/data/codec/

## Purpose

Declares the domain contract every wire-format codec in the SDK satisfies (`Codec`), the optional streaming extension (`StreamingCodec`) and its bounded sibling (`BoundedStreamingCodec`, #891), the optional head-sniffing extension (`Sniffer`, #909, which `Detect` asks), the optional append-into-buffer extension (`Appender`), and the **process-wide registry** that maps `Format` / MIME / file extension to the registered codec. ADR 0003.

No format-specific knowledge lives in this package — concrete codecs live under `internal/service/data/codec/<format>/` and self-register at package import. `pkg/v1/data/codec` blank-imports all sixteen of them (24 Format names) and re-exports `Marshal` / `Unmarshal` / `Lookup*` against this package.

What IS per format below it is the error codes. Each `<format>/` subdirectory is the core mirror of `internal/service/data/codec/<format>/` and holds that package's codes and `errs.Define` sentinels and nothing else (ADR 0160 §2) — eighteen of them: the sixteen codecs plus `strictjson` and `jsonpatch`, which are not codecs; `jsonshape` declares no code and has no mirror. `scratch/` is the payload-recycling threshold every engine shares.

**The ports are generated from the design** (ADR 0163): `Codec`,
`StreamingCodec`, `Encoder`, `Decoder` and `Appender` are declared, with their
doc comments, under `ports:` in `design/data/codec.yaml`, and `kit gen` writes
them into `gen_ports.go`. A port or its doc comment changes in the design,
then `kit gen`, then `make api` — never in `gen_ports.go`, whose header
digests `make api-check` verifies. They moved there from `codec_interface.go`
and `appender.go`, which, left with nothing but their package comment, are gone
(rule 5); the package comment is `doc.go`'s alone, written by kit from the design (ADR 0167).

## Conventions

- **The tables are the kernel's `plugin.Registry`, not copies of it** — codecs Register exactly once at import; everything else is read-many. A frozen-after-init map read through the table's snapshot (one `atomic.Pointer` load) is ~30% faster than `sync.Map.Load` + the interface-to-Codec type assertion (microbench: 9.1 ns vs 12.8 ns). The copy-on-write mechanism and the map clone live in `internal/kernel/plugin` over `internal/kernel/concur/snapshot` (ADR 0011, ADR 0159); `registry.go` keeps only the domain: the strict rule on a `Format` name (`Claim`, refused on `taken`), the alias normalisation, and the conflict's code and fields — an alias conflict names its `owner` from the same atomic `Claim` that refused it. The MIME and extension indexes sit BESIDE the `Format` table, each a table of its own, because the kernel's has no second index.
- **Aliases are normalised symmetrically at registration and lookup.** Extensions are lowercased; MIME types go through `normalizeMIME` (strip parameters via `mime.ParseMediaType`, lowercase, trim; manual `;`-cut fallback on a malformed header) at BOTH `Register` and `LookupMIME` time, so a registered MIME is always reachable. A parameter-only alias therefore normalises to its bare media type and collides loudly rather than hiding behind it — see issue #36 (the former `base64url` `application/base64;url=true` alias was removed for exactly this reason).
- **A `Format` registers once.** A second `Register` under a taken name **panics at boot** — even with the same codec — and so does a MIME type or extension another `Format` holds; only an alias the same `Format` claims twice (two of its MIME types normalising to one key) is accepted. Every panic carries the dotted-quad code in the message; a conflict's is the typed `DuplicateRegistration` with the key that collided (rule 2: the conflict was a `fmt.Errorf("%w")` whose header, `[0.2.2.1 duplicate registration]`, the rule-4 regex could not even match).
- **An unusable plug-in is refused before anything is published.** A nil, a typed nil or a non-comparable codec (`plugin.Unusable`, ADR 0071) panics with `CODEC_NIL` (0.2.2.5) and the concrete type, never with `DUPLICATE_REGISTRATION`.
- **An empty key is refused before anything is published.** An empty `Name`, or a MIME type or extension that is empty once normalised as its `Lookup*` normalises it, panics with `KEY_EMPTY` (0.2.2.6) naming the codec and the slot — never with a `DUPLICATE_REGISTRATION` over `""` that blames whichever codec claimed it first.
- **`Register` reads the codec's keys through the interface, so it orders nothing.** The Go specification (Package initialization) records a dependency only on what an initialiser references — a variable, a function, a method through a non-interface type — so `var Codec = codec.Register(&xCodec{})` is NOT ordered after the package variables `xCodec`'s methods read. gc masks it by laying constant composite literals out statically; `garble -literals` turns them into code and they are still unset when `Register` runs (supervizio/agent#305). A codec's key methods therefore return literals, or the initialiser references the table itself (`&pemCodec{extensions: extensions}`, `baseenc.newVariant`); `registration_order_external_test.go` holds the rule.
- **`Format("")` is reserved** as the invalid zero value — `Known()` returns false; `Lookup` of empty `Format` always misses.
- **`BoundedStreamingCodec` is optional too** (#891): json, xml and cbor implement it — the three stream decoders that held no ceiling — and the facade's `NewBoundedDecoder` returns `STREAMING_UNSUPPORTED` for any other codec. The ceiling bounds one value, counted from the end of the previous one, so a long-lived stream of small values is never refused; a value past it is refused after at most ceiling+1 bytes of it are read.
- **`Sniffer` is optional and must be confident** (#909): a codec claims a head no other format's output starts with — json, ndjson (two records, so it never meets json on the same bytes), xml, pem and bson do; cbor, msgpack, asn1, tlv and the text formats without a head (yaml, toml, csv, form, baseenc) do not, since almost any bytes start one of them. Two claims make `Detect` answer nothing rather than guess.
- **Misuse is the family's, not the format's (#1101)**: every codec's `Unmarshal` and `Decode` calls `CheckTarget` before reading a byte, so a nil or non-pointer target is `TARGET_INVALID` (0.2.2.3) whatever the format — never an `UNMARSHAL_FAILED` that blames the input; json, xml, bson, cbor, msgpack and tlv refuse zero bytes with `EMPTY_INPUT` (0.2.2.2), yaml and toml keep "an empty document leaves v unchanged"; the `Marshal` of the codecs that encode any Go value (json, xml, yaml, toml, cbor, msgpack, bson) calls `CheckValue` first, so a channel, a function or an unsafe pointer is `VALUE_INVALID` (0.2.2.4) — `Append`, the hot path, leaves it to the encoder's `MARSHAL_FAILED`, which kit's inlining budget holds (bson, cbor, msgpack and toml's `Append` inline). The family code is the origin, with no per-format code in the trail: misuse is not a decoding failure. `IsMisuse` reads the three.
- **A decode refusal carries the position it knows, one way (#1125)**: `offset` (0-based byte), `line` and `column` (1-based), absent when unknown, through `PositionFields` or under its three keys — never in a Private sentence alone. A text format places by line and column, a binary format by offset alone; `PositionOf` is the one reader, whatever the format. Codes, reasons and Public sentences do not carry it.
- **`Appender` is optional**; consumers detect it with a type assertion and fall back to `Marshal` + copy. Hot paths (logger record formatting, NDJSON streams) prefer `Appender` when present.

## Do NOT

- Add a `MustRegister` variant — `Register` already panics on duplicate; a second entry-point hides the boot failure.
- Add deregistration / replacement APIs — the registry is append-only by contract.
- Import a service-layer codec from here. Service packages register themselves on import; core stays unaware of which formats exist.
- Inline format-specific logic (compaction, indent, …) into the interface — those belong on the concrete codec's constructor.

## Verification

```
# Primary (Bazel)
bazel test --config=race //internal/core/data/codec:codec_test

# Fallback
cd internal/core && GOWORK=off go test -race -cover ./data/codec/...
# expected: registry concurrency + duplicate-detection + MIME-param stripping +
# Appender detection covered; ≥95% line coverage.
```

The range-ownership audit (`registry_ownership_external_test.go`, against the table kit writes from `design/sdk.yaml`'s `codes.ranges` — ADR 0164 —, in `bazel test //internal/kernel/errs:errs_test`, also run by `make test`) verifies the six `Code*` constants stay in the `0.2.2.*` block `codeRangeOwners` gives this package. The package's sentinels — `DuplicateRegistration` and the three misuse refusals `EmptyInput` / `TargetInvalid` / `ValueInvalid` (#1101) — are audited like any other (reason = the name in SCREAMING_SNAKE); the nil refusal spells its `CODEC_NIL` in the message, the empty-key refusal its `KEY_EMPTY`.
