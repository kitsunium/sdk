# pkg/v1/cli/

## Purpose

The **public facade** for the command-line domain (ADR 0065): sub-commands,
generated help, a typed exit status, and the seam to `config` — the four
things the stdlib's `flag` package deliberately does not have. Type aliases
over `internal/core/cli` and `internal/service/cli`, plus the two helpers a
`main` actually needs (`Status`, `Execute`).

## Why this shape

- **`Status` is a guard, not a second convention.** The exit status is the
  SDK's existing one: `errs.WithExitCode` at the sentinel,
  `errs.ExitCodeOf` at the caller. `Status` adds exactly one thing —
  `errs.ExitCodeOf(nil)` is **70**, because it answers "what status does this
  ERROR map to" and nil is not an error, so
  `os.Exit(errs.ExitCodeOf(app.Execute(…)))` would fail every successful run.
  This is the one place in the SDK where nil has to mean 0, so this is where
  the guard lives. Pinned by `TestStatusIsZeroForSuccess`, which asserts the
  premise as well as the behaviour.
- **`var _ coreconfig.Source = (*FlagSourceValue)(nil)`.** The claim that `cli`
  feeds `config` is worth what its mechanical enforcement is worth: a doc line
  survives a signature change, a compile-time assertion does not.
- **`Execute` exists because the failure it prevents is real.** A caller who
  writes `New` and forgets to check its error, then calls `Execute` on a nil
  `Executor`, gets a nil dereference instead of `EX_CONFIG`.
- **`Config.Output` and `Config.ErrOutput` both default to `os.Stderr`.** ADR
  0030: stdout is a protocol channel no SDK default may claim. Two writers
  rather than one so a tool that sets `Output: os.Stdout` for a machine-readable
  document does not get a help page in the middle of it.

## Do NOT

- **Hand-edit `README.md`** — it is generated by `gomarkdoc` from this
  package's doc comment (rule 10). Edit `cli.go`, then `go generate ./...` or
  `make docs-readme`.
- **Add a second exit-status API.** `errs.WithExitCode` / `errs.ExitCodeOf` is
  the convention; `Status` is its nil guard and nothing more.
- **Import `os` here for anything but a writer default.** No `os.Exit`, no
  `os.Args`: `Execute` takes the vector so a CLI stays testable and embeddable,
  and `main` is the only place that ends the process.
