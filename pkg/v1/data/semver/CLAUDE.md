# pkg/v1/data/semver/

## Purpose

Public facade for `internal/kernel/semver` (ADR 0156 §4, published by ADR 0159
§4): SemVer 2.0.0 precedence with Go's leading `v`, and Go pseudo-versions.
Six forwarding functions — no type, no behaviour of its own. Stdlib-only →
dep-light; cross-OS portable.

It exists for the framework. The distribution mechanisms that compare versions
— `selfupdate`, `entitlement` — moved out of the SDK into `framework/`
(ADR 0158), which reaches the SDK through `pkg/v1` and `kernel/errs` only
(ADR 0147), and call this package. Without it they would have kept
`golang.org/x/mod` in the framework's graph, or re-implemented precedence a
third time. It sits in the `data` family, at `pkg/v1/data/semver`, as the
reorganisation's target tree places it — a version string is data a program
compares (`pkg/v1/data/CLAUDE.md`) — and not at the root of `pkg/v1` beside
`errs` and `clock`, where ADR 0155 §1 and ADR 0159 §4 wrote it; the kernel
package it forwards to stays at the kernel's root.

## Surface

| Symbol | Notes |
|---|---|
| `IsValid(v)` | SemVer 2.0.0 with a leading `v`, plus the `vMAJOR` / `vMAJOR.MINOR` shorthands |
| `Compare(v, w)` | -1 / 0 / +1 by SemVer §11; build metadata ignored; an invalid string below every version and equal to every other invalid string — a total order `slices.SortFunc` can use |
| `Prerelease(v)` | the pre-release with its `-`, or `""` for a release AND for an invalid string — `IsValid` tells them apart |
| `IsPseudoVersion(v)` | the three shapes of the Go modules reference, with or without build metadata |
| `PseudoVersionRev(v)` | `(revision, ok)` — x/mod answered `(revision, error)` |
| `PseudoVersionTime(v)` | `(time in UTC, ok)` — `false` also for a stamp whose digits are no instant |

That is the complete exported surface of `internal/kernel/semver`, and the
names and answers of `golang.org/x/mod/semver` and `golang.org/x/mod/module`
for those six: a call site moves by changing its import (and, for the two
pseudo-version readings, `err == nil` to `ok`).

## Conventions

- **Forwarding functions, not `var` aliases.** Each function is declared here
  with its own doc comment, so `go doc`, pkg.go.dev and the generated README
  document it — a `var IsValid = ksemver.IsValid` would render as a variable of
  function type.
- **No allocation**, inherited: the kernel's race-off alloc gate pins it.
- README generated by gomarkdoc; edit the `semver.go` doc comment and run
  `make docs-readme`.

## Do NOT

- Add `Canonical`, `Major`, `MajorMinor`, `Build`, `Sort` or `Max` here first.
  A new reading lands in `internal/kernel/semver` — as `(string, bool)`, never
  x/mod's `""`-for-invalid — and is forwarded in the same change. A published
  function is frozen at v1; an added one breaks nobody, which is why the
  surface starts at what is called.
- Add a helper, a default or a normalisation (adding a missing `v`, trimming
  whitespace). `selfupdate` and `entitlement` normalise their own input,
  differently, on purpose; a facade that grows logic is a second
  implementation.
- Reach for `internal/kernel/semver` in this package's tests. The test names
  `pkg/v1` only, so it proves the public surface rather than the kernel's.

## Generated

`facade_gen.go` is kit's (ADR 0165): every alias, re-exported constant and variable, and forwarder of this package is declared in the `facade:` of `design/kernel/semver.yaml`, doc comments included, and kit writes it. Where this file names another file as holding one of them, read `facade_gen.go`: the hand-written files keep the package comment and the declarations of their own. Change a re-export, or its doc comment, in the design and run `kit gen` (then `make api` and `make docs-readme`); `make api-check` fails on a `facade_gen.go` edited by hand.
