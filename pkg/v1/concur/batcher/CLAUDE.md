# pkg/v1/concur/batcher/

## Purpose

Public facade for `internal/kernel/concur/batcher` (ADR 0159 §4, ADR 0014):
coalesce items and hand them to a caller's deliver function a batch at a time
— at a count or a weight cap, on a ticker that runs on an injected clock, or
on `Flush` / `Close`. Aliases, one forwarding constructor and the two
sentinels — no behaviour of its own. Stdlib-only → dep-light; cross-OS
portable.

It is the primitive under the logger's database sink and the AWS writers,
published so a program — and the framework, which reaches the SDK through
`pkg/v1` alone (ADR 0147) — batches its own round trips on it.

## Surface

| Symbol | Notes |
|---|---|
| `Batcher[T]` | alias; `Add` / `Flush` / `Close`, each taking a context. Safe from any number of goroutines |
| `Config[T]` | alias; `MaxItems`, `MaxWeight` + `WeightOf`, `FlushEvery` + `Clock`, `OnError`. The zero value is usable: no cap, no ticker |
| `Sink[T]` | alias of `func(ctx, batch []T) error`; never entered concurrently, two racing batches unordered |
| `NewBatcher[T](deliver, cfg)` | a positive `FlushEvery` spawns the ticker goroutine `Close` joins |
| `BatcherClosed` | `0.1.5.1` — `Add` / `Flush` after `Close` |
| `BatcherDeliverFailed` | `0.1.5.2` — wraps the deliver function's error, the cause still reachable through `errors.Is` |

That is the complete exported surface of `internal/kernel/concur/batcher`
except the two `Code*` constants: as in every facade, a caller matches a
sentinel with `errors.Is`, or by code with `errs.HasCode(err, code)` after
`errs.CodeOf(batcher.BatcherDeliverFailed)` — the code VALUES stay the
kernel's, unchanged (ADR 0160 §3).

## Conventions

- **The names are the kernel's**, stutter included (`batcher.NewBatcher`,
  `batcher.BatcherClosed`): a pure alias facade does not rename, so a reader
  moving between the kernel and the facade meets one vocabulary.
- **What the kernel comment got wrong, the facade says right.** `Close`
  delivers what is pending with the context it is GIVEN; the kernel comment
  said "under a background context" and is corrected in the same change.
- **Methods and fields are documented on the alias** and linked
  `[Batcher].Add`, `[Config].MaxItems` (ADR 0138).
- README generated by gomarkdoc; edit the `batcher.go` doc comment and run
  `make docs-readme`.

## Do NOT

- Add a retry, a persistence layer or an asynchronous `Add` here: the batcher
  is not a queue, and `data/queue` is the durable one. A shape the alias
  cannot express lands in the kernel package first.
- Re-export the `Code*` constants as new symbols; the sentinels carry them.
- Reach for `internal/kernel/concur/batcher` in this package's tests.

## Generated

`facade_gen.go` is kit's (ADR 0165): every alias, re-exported constant and variable, and forwarder of this package is declared in the `facade:` of `design/kernel/concur.yaml`, doc comments included, and kit writes it. Where this file names another file as holding one of them, read `facade_gen.go`: the hand-written files keep the package comment and the declarations of their own. Change a re-export, or its doc comment, in the design and run `kit gen` (then `make api` and `make docs-readme`); `make api-check` fails on a `facade_gen.go` edited by hand.

## Verification

```
bazel test --config=race //pkg/v1/concur/batcher:batcher_test
cd pkg && GOWORK=off go test -race ./v1/concur/batcher/
```

`batcher_external_test.go` is `package batcher_test` and names `pkg/v1` only:
delivery at the item cap and at the weight cap and not before, `Flush` and
`Close` delivering what is pending, `BatcherClosed` after `Close` and a second
`Close` that is a no-op, a deliver failure matched by `errors.Is` and by code
through `pkg/v1/errs`, the `FlushEvery` ticker driven by a
`pkg/v1/clock.ManualClock` — plus `ExampleNewBatcher`.
