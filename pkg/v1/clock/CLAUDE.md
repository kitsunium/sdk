# pkg/v1/clock/

## Purpose

Public facade for the SDK's time port (ADR 0090). Re-exports
`internal/kernel/clock` **in full** as type aliases — no behaviour, no wrapper,
no new symbol. Stdlib-only → dep-light; cross-OS portable.

It exists to close a hole rather than to add a capability. Every SDK
configuration that takes a time source aliases an internal struct whose `Clock`
field is typed `clock.Clock` or `clock.Timed`, so those names were already in
the public API — visible in godoc, and named verbatim in the compiler's own
error at a consumer's call site. But `Waiter.NewTimer` / `NewTicker` return
`Timer` / `Ticker`, Go compares method signatures by **type identity** rather
than by method set, and the package declaring them was behind `internal/`. So
`Timed` was unimplementable from outside the module and its `Clock` field could
only hold nil.

Nine configurations were affected, counted by resolving every `pkg/v1` alias
to its internal type rather than by reading: `scheduler.Config`,
`lock.MemoryConfig`, `lock.FileConfig`, `lock.KeepaliveConfig`,
`session.FileConfig`, `sql.Config`, `health.Config`, `lifecycle.Config`,
`queue.ConsumerConfig` — none of them deterministically testable by a
downstream consumer. Fourteen more carry a `clock.Clock`, which a two-method
double could always satisfy structurally; what those lacked was a NAME for the
type and any way to reach `System`.

## Surface

| Symbol | Notes |
|---|---|
| `Clock` | reads time — `Now` / `Since`. **Frozen at two methods** |
| `Waiter` | waits for time — `After` / `NewTimer` / `NewTicker` / `Sleep` |
| `Timed` | the union; what every `Clock clock.Timed` field asks for |
| `Timer` / `Ticker` | the handles `Waiter` returns. **Aliases, which is the load-bearing part** — a locally declared interface with the same methods is a different type and does not satisfy `Waiter` |
| `System` | the production `Timed`, delegating to package `time`. A VALUE, not a hook |
| `ManualClock` | the deterministic double — `Advance` / `Set` / `Pending` / `BlockUntil` on top of `Timed`. No exported field |
| `NewManualClock(start)` | the only constructor; any instant is legal |

That is the complete exported surface of `internal/kernel/clock`. Nothing is
held back and nothing is added.

## Conventions

- **Type aliases, not new types** — `pkg/v1/clock.Ticker` IS the kernel type.
  Redeclaring any of the five interfaces would reproduce the exact defect this
  package was created to fix.
- **The five interfaces are frozen** (ADR 0039). A new time capability lands on
  a SIBLING interface reached by type assertion, never by widening one of
  these — a downstream double is now possible, so widening would break it at
  compile time with no deprecation window.
- **`System` is a value, not an override hook.** Assigning to it rebinds this
  package's variable and changes nothing inside the SDK, which reads its own
  default directly. To give a component another clock, set that component's
  `Clock` field.
- README generated by gomarkdoc; edit the `clock.go` doc comment and run
  `make docs-readme`.

## Do NOT

- Add a method to `Clock`, `Waiter`, `Timed`, `Timer` or `Ticker`.
- Add a helper, a default, a constructor or a convenience wrapper here. If an
  alias does not suffice, the shape belongs in `internal/kernel/clock` and the
  facade re-exports it — a facade that grows logic is a second implementation.
- Reach for `internal/kernel/clock` in this package's tests. A test that
  imports it proves the opposite of what this package claims; the precedent is
  `pkg/v1/token`, whose facade test hid two constructors no downstream module
  could call.

## Verification

```
bazel test --config=race //pkg/v1/clock:clock_test
```

`clock_external_test.go` is `package clock_test` and names `pkg/v1` only. It
asserts the nine `Timed`-bearing configurations accept a hand-written clock,
that a two-method double still reaches a `Clock`-typed field, that `System` is
referenceable, and that a `ManualClock` fires a real scheduler with no
`time.Sleep` and no wall-clock wait.
