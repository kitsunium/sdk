# Bazel targets for the race-off allocation lane (`--config=alloc`).
#
# Single source of truth, consumed by three call sites so they cannot drift:
#   - Makefile              → `make test-alloc`
#   - .github/workflows/bazel-ci.yml → the "alloc + zero-alloc gates" step
#   - scripts/pre-commit/check-alloc-lane-coverage.sh → the drift guard
#
# WHY this lane exists: a test file carrying `//go:build !race` is NOT compiled
# by the race suite (`bazel test --config=ci //...`, race on by default). Such a
# file therefore runs in EXACTLY ONE place — here. A `!race` test whose package
# is missing from this list runs nowhere at all, silently: it compiles, it is
# never executed, and no lane reports it as skipped.
#
# That is not hypothetical. Before this file existed the list held only the two
# entries below marked (original), and four `!race` files ran in zero lanes —
# including `pkg/v1/logger`'s regression test pinning the "Build().Send() is NOT
# allocation-free" contract, i.e. the very guard against the doc claim it exists
# to police.
#
# INVARIANT (enforced by check-alloc-lane-coverage.sh, wired into `make lint`):
#   every directory containing a `//go:build !race` *_test.go file must be
#   covered by an entry below, either directly or via a `/...` prefix.
# Adding a `!race` test to a new package? Add its go_test target here in the
# same commit, or the guard fails the build.

# Build().Send() one-alloc-per-emit contract — the guard behind the
# "zero-allocation logger" claim in README.md / CLAUDE.md. Also pins fan-out

//pkg/v1/logger:logger_test
# The two steady-state allocation claims RFC 6455's frame reader is sold on:
# the reassembly buffer is reused across messages and the write buffer across
# frames, so neither Receive nor Send allocates once a connection is warm. Both
# are stated in Receive's doc comment, in initialWriteCapacity's and in the
# package CLAUDE.md, and both were unguarded until 2026-09. Each is
# mutation-checked in its own doc comment.
//internal/service/net/websocket:websocket_test
# The two allocation claims an event stream is sold on, neither of which had a
# gate: initialFrameCapacity's "a steady-state send allocates nothing" (true,
# but only above the buffer's high-water mark) and the price of the retention
# ceiling that now bounds that mark — an outsized frame must allocate, because
# the alternative is pinning its size for the stream's whole life. Each is
# mutation-checked in its own doc comment.
//internal/service/net/sse:sse_test
# The two allocation claims the outbound client's own comments made and its code
# contradicted. guard.go said "a nil hook costs one comparison per call" while
# installing the observation record AND the closure that fills it on every
# response — two heap allocations per request for the DEFAULT configuration,
# 65 % of the objects the profile attributed to guard.RoundTrip. And path.go
# lowercased the whole path and every segment to compare them against six ASCII
# constants, so the safety checks allocated on any path carrying an uppercase
# byte — which url.URL.EscapedPath emits by construction (%2F, never %2f), and
# which a canonical UUID carries on a path that is not adversarial at all. Both
# are gated at zero/one now, and each is mutation-checked in its doc comment.
//internal/service/net/client:client_test
# The two default writers (ADR 0015) and the severity floor in front of them,
# against the SDK's flagship claim: "one alloc per emit". pkg/v1/logger's
# TestV116BuildSendAllocatesOnePerEmit ends at the handler, and nothing had ever
# measured what a WRITER adds underneath it. The answer is nothing — the
# allocation profile of a full emit puts 99.53 % (console) / 95.92 % (file) of
# its objects on the handler's attrs clone and 0 on the transport — and the
# three tests here make that a property rather than an observation. The gate is
# the writer's DELTA against a transport-free emit, not a constant, so it does
# not couple to the clone it does not own.
#
# levelgate's is the one with teeth of its own: a dropped record must cost
# nothing at all, since its whole cost is paid by the caller who configured the
# floor so that work would not happen. Each is mutation-checked in its doc
# comment, and all three count a TOTAL malloc delta rather than calling
# testing.AllocsPerRun — whose integer division reported 0.0 for a mutation that
# really did allocate.
//internal/service/writer/levelgate:levelgate_test
//internal/service/writer/console:console_test
//internal/service/writer/file:file_test
# The two claims the CVE-2025-30204 defence rests on, both stated in three
# places (splitCompact's doc comment, segmentsValue's, and the package
# CLAUDE.md §Bounds) and both unguarded until 2026-09: splitting a well-formed
# token allocates NOTHING, because the parts are views held in a fixed
# [4]string array rather than a slice a separator count can grow; and refusing
# an oversized token does not scan it, because the length bound is checked
# first. A regression to strings.Split is invisible to every functional test in
# the package — it returns exactly the same parts — and the second test found
# that the obvious hostile input (megabytes of ".") does not force the scan at
# all, while a separator-free token of the same size does. Each is
# mutation-checked in its own doc comment.
//internal/service/token:token_test
# The two claims that decide whether tracing belongs in a DEFAULT middleware
# stack, neither of which had a gate — or a number — until 2026-09. A traced
# request's latency surcharge is ~1.3 % of a full SDK HTTP request, which nobody
# would reject a middleware over; its ALLOCATION surcharge is +19 % against a
# 63-allocation baseline, which at high RPS is a GC-pressure story. So the
# budget is expressed in allocations, per request, sampled AND unsampled, and a
# regression in it is a regression in the argument.
#
# The second is the overflow path: past MaxSpans a span is REFUSED, and refusing
# it must cost less than keeping it — otherwise a recorder nobody is draining,
# the exact situation the bound exists to survive, becomes the most expensive
# state the type has. Its mutation is the one that vindicates counting totals:
# appending the dropped span's name allocated 9 times over 500 calls, which
# testing.AllocsPerRun divides as integers and reports as 0.0.
#
# Each is mutation-checked in its own doc comment, and the first records a
# mutation that was DISCARDED for not modelling a defect.
//internal/service/trace:trace_test
